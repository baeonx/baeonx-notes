## **Deparser 为空时，tshark -V 的表现**

### **实验：删除所有 emit**

```cpp
control MyDeparser(packet_out packet, in headers hdr) {
    apply {
        // 完全空的 deparser
        // 没有任何 packet.emit()
    }
}
```

### **tshark -V 输出**

```bash
tshark -r pcaps/s1-eth1_out.pcap -V -c 1
```

**你会看到**：

```bash
root@5f755f73d839:/workspace/tutorials/exercises/mri# tshark -r pcaps/s1-eth1_out.pcap -V -c 1
Running as user "root" and group "root". This could be dangerous
```

## **关键特征（Deparser 为空时）**

### **1. 帧信息中的协议列表**

```
[Protocols in frame: eth:ethertype:ip:icmp:data]
```

虽然头都是空的，但 `tshark` 仍然尝试按 **Ethernet → IPv4 → ICMP** 解析。

### **2. 所有字段都是 0 或空值**

```
Ethernet II, Src: 00:00:00:00:00:00, Dst: 00:00:00:00:00:00
Source Address: 0.0.0.0
Destination Address: 0.0.0.0
```

- MAC 全是 `00:00:00:00:00:00`
- IP 全是 `0.0.0.0`
- TTL = 64（默认值）
- 校验和 = 0x0000

### **3. 没有报错！**

`tshark -V` **不会报任何错误**，因为它只是"尝试"按协议树解析这些字段，即使全是 0 也**不会报错**。

------

## **为什么 tshark 不报错？**

因为 `tshark` 是**协议解析器**，不是**验证器**：

- `tshark` 看到数据 → 尝试匹配协议模板 → 显示对应字段
- 即使用户字段都是 0，它也**认为这是合法的包**（只是所有字段都是 0）
- 它不会说"这个包不对"，只会显示"这个包的 MAC 是 00:00:00:00:00:00"
