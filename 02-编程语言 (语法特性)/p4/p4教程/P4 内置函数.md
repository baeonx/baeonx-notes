# P4 内置函数从零基础到进阶教程

> 面向对象：P4-16 语言 + v1model 架构（BMv2 软件交换机），全部示例均已用 `p4c --target bmv2 --arch v1model` 实测验证。
>
> 说明：
> - **内置函数 = 语言内置方法 + 核心库（core.p4）extern + 架构（v1model.p4）extern**。它们不是"标准库函数"那样由你调用即可，而是受 P4 规范和使用场景约束（例如 `verify` 只能在 parser 中调用）。
> - 每节结构：**函数签名 → 作用 → 注意事项 → 示例**。示例放在每节最后。
> - 标注 ⚠️ 的内容是"规范允许但 BMv2/p4c 当前未实现"的差异，写代码前务必确认你的 Target。

## 第 0 章 预备知识

### 0.1 内置函数从哪来

| 来源 | 内容 | 位置 |
| :--- | :--- | :--- |
| **语言内置方法** | header 的 `isValid/setValid/setInvalid`、header stack 的 `next/last/size/push_front/pop_front`、编译期大小函数 | P4-16 规范 §8.17/§8.18/§9 |
| **核心库 `core.p4`** | `packet_in`（extract/lookahead/advance/length）、`packet_out`（emit）、`verify`、`static_assert`、`NoAction`、`match_kind` | 规范附录 D |
| **架构库 `v1model.p4`** | 校验和、随机、哈希、digest、clone、recirculate、resubmit、有状态 extern（counter/register/meter/action_profile）等 | 随 p4c 分发 |

### 0.2 三种调用形式

```cpp
# ① 顶层 extern 函数：直接调用
verify(condition, error.SomeError);

# ② 对象方法：对象.方法()
b.extract(hdr.ethernet);      // packet_in 对象 b 的方法
hdr.ipv4.setValid();          // header 对象的方法

# ③ 编译期函数 / 断言
const bool c = static_assert(V1MODEL_VERSION > 20180000, "version too old");
```

### 0.3 参数方向速记

| 方向 | 含义 | 特点 |
| :--- | :--- | :--- |
| `in` | 输入 | 只读，调用时拷贝实参值 |
| `out` | 输出 | 只能写，实参必须是左值，返回时拷回 |
| `inout` | 输入输出 | 先读后写，实参必须是左值 |
| 无方向 | 编译期常量（函数）或控制面数据（action） | 由程序/控制面提供 |

### 0.4 一个贯穿全文的最小框架

```cpp
#include <core.p4>
#include <v1model.p4>

header ethernet_h { bit<48> dstAddr; bit<48> srcAddr; bit<16> etherType; }
struct headers { ethernet_h ethernet; }
struct metadata { }

parser MyParser(packet_in b, out headers hdr, inout metadata meta,
                inout standard_metadata_t standard_metadata) {
    state start {
        b.extract(hdr.ethernet);
        transition accept;
    }
}

control MyIngress(inout headers hdr, inout metadata meta,
                  inout standard_metadata_t standard_metadata) {
    apply { /* 各示例的代码写在这里 */ }
}

control MyEgress(inout headers hdr, inout metadata meta,
                 inout standard_metadata_t standard_metadata) { apply { } }
control MyVerifyChecksum(inout headers hdr, inout metadata meta) { apply { } }
control MyComputeChecksum(inout headers hdr, inout metadata meta) { apply { } }
control MyDeparser(packet_out b, in headers hdr) {
    apply { b.emit(hdr.ethernet); }
}

V1Switch(MyParser(), MyVerifyChecksum(), MyIngress(),
         MyEgress(), MyComputeChecksum(), MyDeparser()) main;
```

> 下面的示例，除特别说明外，都可以把 `apply {}` 里的代码替换进 `MyIngress`（parser 类函数替换进 `MyParser`）。

# 第 1 章 基础篇

## 1. verify()

**签名（核心库）：**

```cpp
extern void verify(in bool check, in error toSignal);
```

**作用：** P4 中最常用的错误处理函数，**只能在 parser 中使用**（规范 §13.7）。当 `check` 为 `true` 时无副作用；为 `false` 时，立即把 parser 错误码设为 `toSignal` 并跳转到 `reject` 状态（丢弃报文）。相当于 C 语言的 `assert`。

**注意事项：**
- ⚠️ 只能在 parser 中调用（p4c 报错：`may only be invoked in parsers`）。
- 第二个参数必须是 `error` 类型；自定义错误要先 `error { ... }` 声明。
- 校验失败后 parser 终止，后面的状态不再执行。

**示例（放在 parser 里，校验 IPv4 版本与头部长度）：**

```cpp
error { IPv4IncorrectVersion, IPv4OptionsNotSupported }

state parse_ipv4 {
    b.extract(hdr.ipv4);
    verify(hdr.ipv4.version == 4w4, error.IPv4IncorrectVersion);   // 版本必须为 4
    verify(hdr.ipv4.ihl == 4w5, error.IPv4OptionsNotSupported);    // 头部必须是 20 字节（无选项）
    transition accept;
}
```

## 2. extract()

**签名（核心库 `packet_in`）：**

```cpp
extern packet_in {
    void extract<T>(out T hdr);                                   // 固定长度提取
    void extract<T>(out T variableSizeHeader, in bit<32> variableFieldSizeInBits);  // 变长提取
}
```

**作用：** 从报文当前游标处读取数据填入 header，并把游标前移相应位数。**只有 parser 里能调用**。提取成功后，该 header 的 validity 位自动置为 `true`。

**注意事项：**
- `T` 必须是 header 类型（固定长度版）或"只含 1 个 `varbit` 字段"的 header（变长版）。
- 报文数据不足会触发 `error.PacketTooShort`；提取超长会触发 `error.HeaderTooShort`。
- 变长版第二个参数指定 `varbit` 字段的实际位数（不是整个 header 的长度）。
- 对 header stack 提取时用 `.next`（见 3.16）。

**示例 1（固定长度，提取以太网头 + IPv4 头）：**

```cpp
header ethernet_h { bit<48> dstAddr; bit<48> srcAddr; bit<16> etherType; }
header ipv4_h { bit<4> version; bit<4> ihl; bit<8> ttl; bit<8> protocol;
                bit<16> hdrChecksum; bit<32> srcAddr; bit<32> dstAddr; }

state start {
    b.extract(hdr.ethernet);
    transition select(hdr.ethernet.etherType) {
        0x0800 : parse_ipv4;
        default: accept;
    }
}

state parse_ipv4 {
    b.extract(hdr.ipv4);
    transition accept;
}
```

**示例 2（变长提取 IPv4 选项，`varbit` 放 header 末尾）：**

```cpp
header ipv4_opt_h {
    bit<4> version; bit<4> ihl; bit<8> ttl; bit<8> protocol;
    bit<16> hdrChecksum; bit<32> srcAddr; bit<32> dstAddr;
    varbit<320> options;                     // 最多 320 位
}

state parse_ipv4 {
    b.extract(hdr.ipv4);                     // 先提取固定部分
    bit<16> opt_len = (bit<16>)(hdr.ipv4.ihl - 5) * 32;   // 选项长度 = (ihl-5)*32 位
    transition select(hdr.ipv4.ihl) {
        5 : accept;                          // 无选项
        _ : parse_ipv4_options;
    }
}

state parse_ipv4_options {
    b.extract(hdr.ipv4, opt_len);            // 动态指定 varbit 的实际位数
    transition accept;
}
```

## 3. lookahead()

**签名（核心库 `packet_in`）：**

```cpp
T lookahead<T>();
```

**作用：** 从报文当前游标处读取数据，**但游标不移动**。常用于"先看看再决定怎么解析"，比如读取 EtherType 决定下一步。

**注意事项：**
- 返回类型 `T` 必须是固定大小类型，且必须显式指定类型参数。
- 数据不足时表现与 Target 相关（规范允许报 `PacketTooShort`）。
- 因为不推进游标，之后还是要用 `extract` 真正提取。

**示例（先预读 EtherType，再决定解析路径）：**

```cpp
state start {
    bit<16> peek = b.lookahead<bit<16>>();   // 预读，游标不动
    // 此时 peek 是当前游标处的 16 bit，通常配合 extract 使用
    b.extract(hdr.ethernet);                 // 真正提取
    transition select(hdr.ethernet.etherType) {
        0x0800 : parse_ipv4;
        0x86dd : parse_ipv6;
        default: accept;
    }
}
```

> 更常见的用途：`b.lookahead<T>()` 先判协议再决定调用哪个 `extract`，避免解析路径写死。

## 4. advance()

**签名（核心库 `packet_in`）：**

```cpp
void advance(in bit<32> sizeInBits);
```

**作用：** 把报文游标向前移动 `sizeInBits` 位，**不提取任何数据**。用于跳过不需要解析的字段（如 VLAN 标签、填充位）。

**注意事项：**
- 参数是位数（不是字节数）。
- 跳过过多导致越界时触发 `PacketTooShort`。
- 若跳过的位数是字节对齐的，语义与 `extract` 一个空字段等价，但更节省。

**示例（跳过 VLAN 的 4 字节标签后再解析）：**

```cpp
state parse_vlan {
    b.advance(32);           // 跳过 4 字节 = 32 位的 VLAN 头
    transition parse_ipv4;
}

state parse_ipv4 {
    b.extract(hdr.ipv4);
    transition accept;
}
```

## 5. length()

**签名（核心库 `packet_in`）：**

```cpp
bit<32> length();
```

**作用：** 返回整个报文的长度（**字节**数）。可用于统计、校验包大小等。

**注意事项：**
- ⚠️ BMv2 后端**不支持**（p4c 报错：`b.length(): not supported in parser on this target`），使用前先确认 Target。
- 只能在 parser 中使用（它是 `packet_in` 的方法）。

**示例（丢弃太小的报文，BMv2 不可用，仅作规范示范）：**

```cpp
state start {
    bit<32> len = b.length();            // 报文长度（字节）
    verify(len >= 14, error.PacketTooShort);   // 至少要有以太网头
    b.extract(hdr.ethernet);
    transition accept;
}
```

## 6. emit()

**签名（核心库 `packet_out`）：**

```cpp
extern packet_out {
    void emit<T>(in T hdr);
}
```

**作用：** 把 header 写入输出报文并推进游标。**只能在 deparser（一个 control）中调用**。对 header 只发送 `valid == true` 的；对 header stack / struct / header_union 会递归 emit 每个元素/成员。

**注意事项：**
- `T` 可以是 header、header stack、header_union 或由这些组成的 struct。
- 不能 emit 基础类型、`error`、`enum`（无法序列化）。
- emit 顺序就是报文中字段的排列顺序。
- 报文的数据部分（payload）会被隐含地发送，无需也不应 emit。

**示例（按顺序组装报文）：**

```cpp
control MyDeparser(packet_out b, in headers hdr) {
    apply {
        b.emit(hdr.ethernet);   // 以太网头
        b.emit(hdr.ipv4);       // 只有 valid 才加入（非 IPv4 报文自动跳过）
        b.emit(hdr.tcp);
        b.emit(hdr.udp);
    }
}
```

## 7. isValid() / setValid() / setInvalid()

**签名（header 内置方法）：**

```cpp
bool isValid();
void setValid();
void setInvalid();
```

**作用：** 操作 header 的隐藏 validity 位。
- `isValid()`：判断 header 是否有效（是否被解析/手动置位）。
- `setValid()`：置有效（之后对该 header 的读写才生效）。
- `setInvalid()`：置无效（emit 时会跳过它）。

**注意事项：**
- **对 invalid 的 header 赋值不生效**！必须先 `setValid()`。
- 声明 header 局部变量时 validity 自动为 `false`。
- header stack 的元素、header_union 的成员同样适用。

**示例（根据协议动态插入/删除头）：**

```cpp
apply {
    // 删除 IPv4 头
    hdr.ipv4.setInvalid();

    // 手动构造并插入一个 VLAN 头（先置位再赋值）
    hdr.vlan.setValid();
    hdr.vlan.vid = 12w100;
    hdr.vlan.pcp = 3w1;

    // 根据有效性分支
    if (hdr.ipv4.isValid()) {
        standard_metadata.egress_spec = 1;
    } else {
        standard_metadata.egress_spec = 2;
    }
}
```

## 8. NoAction

**定义（核心库）：**

```cpp
@noWarn("unused")
action NoAction() {}
```

**作用：** 内置的"什么都不做"动作，常用于表的 `default_action`。核心库已经定义好了，直接引用即可（也可以自己重新定义一个同名 action 覆盖它）。

**注意事项：**
- 自定义同名 action 会触发 `shadow` 警告（无碍，但建议改名，如 `my_no_action`）。
- 它是 action，不是函数，只能出现在表动作列表 / default_action / 显式调用中。

**示例（作为表的默认动作）：**

```cpp
table mac_table {
    key = { hdr.ethernet.dstAddr : exact; }
    actions = { forward; NoAction; }
    default_action = NoAction();        // 未命中 → 什么都不做
    size = 1024;
}

apply {
    mac_table.apply();
}
```

## 9. static_assert()

**签名（核心库）：**

```cpp
extern bool static_assert(bool check, string message);
extern bool static_assert(bool check);       // 重载：使用默认提示信息
```

**作用：** 编译期断言。`check` 为 `false` 时**编译直接失败**并打印 `message`。返回 `bool`，可赋给全局常量以便在编译期做条件检查。

**注意事项：**

- 参数必须是**编译期可求值**的表达式（不能依赖运行时的包内容）。
- 第二个参数是 `string` 常量。
- 常配合宏/常量做版本、位宽、表项数量校验。

**示例（校验架构版本和位宽）：**

```cpp
const bool _v1 = static_assert(V1MODEL_VERSION > 20180000, "Expected v1model >= 2018.06");

const bit<16> W = 32;
const bool _w = static_assert(W >= 32, "Bit width too small");   // ✅ 通过

// ❌ 若取消下面注释，编译会失败并打印 "Table size must be >= 1024"
// const bool _t = static_assert(512 >= 1024, "Table size must be >= 1024");
```

# 第 2 章 进阶篇

## 10. verify_checksum() / update_checksum()（及其 `_with_payload` 变体）

**签名（v1model.p4）：**

```cpp
extern void verify_checksum<T, O>(in bool condition, in T data, in O checksum, HashAlgorithm algo);
extern void update_checksum<T, O>(in bool condition, in T data, inout O checksum, HashAlgorithm algo);
extern void verify_checksum_with_payload<T, O>(in bool condition, in T data, in O checksum, HashAlgorithm algo);
extern void update_checksum_with_payload<T, O>(in bool condition, in T data, inout O checksum, HashAlgorithm algo);
```

**作用：**
- `verify_checksum`：在 **VerifyChecksum control** 中校验数据校验和。校验失败时把 `standard_metadata.checksum_error` 置 1。
- `update_checksum`：在 **ComputeChecksum control** 中计算校验和并写回 `checksum` 字段。
- `_with_payload` 变体：把**未解析的 payload** 也纳入计算（如 TCP/UDP 伪头校验和场景）。

**注意事项：**
- `data` 必须是**字段列表（list）表达式**，BMv2 不支持传整个 header 对象。
- 只能分别在 VerifyChecksum / ComputeChecksum 两个 control 里调用，位置写错会报错。
- `O`（checksum 类型）与 `algo` 必须匹配，常用 `HashAlgorithm.csum16`。
- `condition` 为 `false` 时：verify 直接通过，update 不写结果。
- 校验和算法：`csum16` 是"16 位二进制补码求和（RFC 1071）"。

**示例（验证 + 重算 IPv4 校验和）：**

```cpp
// ── VerifyChecksum control：验证 ──
control MyVerifyChecksum(inout headers hdr, inout metadata meta) {
    apply {
        verify_checksum(
            hdr.ipv4.isValid(),              // 条件
            { hdr.ipv4.version, hdr.ipv4.ihl, hdr.ipv4.diffserv, hdr.ipv4.totalLen,
              hdr.ipv4.identification, hdr.ipv4.flags, hdr.ipv4.fragOffset,
              hdr.ipv4.ttl, hdr.ipv4.protocol,
              hdr.ipv4.srcAddr, hdr.ipv4.dstAddr },   // 数据（不含 checksum 字段）
            hdr.ipv4.hdrChecksum,            // 期望校验和字段
            HashAlgorithm.csum16
        );
    }
}

// ── ComputeChecksum control：重算 ──
control MyComputeChecksum(inout headers hdr, inout metadata meta) {
    apply {
        update_checksum(
            hdr.ipv4.isValid(),
            { hdr.ipv4.version, hdr.ipv4.ihl, hdr.ipv4.diffserv, hdr.ipv4.totalLen,
              hdr.ipv4.identification, hdr.ipv4.flags, hdr.ipv4.fragOffset,
              hdr.ipv4.ttl, hdr.ipv4.protocol,
              hdr.ipv4.srcAddr, hdr.ipv4.dstAddr },
            hdr.ipv4.hdrChecksum,            // 写回这里
            HashAlgorithm.csum16
        );
    }
}
```

> 为什么 TTL 修改后要重算？因为 `update_checksum` 会基于当前字段值重算并覆盖旧校验和，保证发出时校验正确。

## 11. random()

**签名（v1model.p4）：**

```cpp
extern void random<T>(out T result, in T lo, in T hi);
```

**作用：** 生成 `[lo, hi]` 区间内的伪随机数，写入 `result`。常用于负载均衡、抽样、哈希选路。

**注意事项：**
- 三个参数类型必须一致（同宽度的 bit 或 int）。
- `result` 是 `out`，实参必须是左值。
- 区间要合法（`lo <= hi`），否则行为与 Target 相关。

**示例（按 10% 概率丢弃/抽样）：**

```cpp
apply {
    bit<32> r;
    random(r, 32w0, 32w99);                 // 生成 0~99 的随机数
    if (r < 32w10) {
        mark_to_drop(standard_metadata);    // 10% 丢弃
    } else {
        standard_metadata.egress_spec = 1;  // 其余转发
    }
}
```

## 12. hash()

**签名（v1model.p4）：**

```cpp
extern void hash<O, T, D, M>(out O result, in HashAlgorithm algo,
                             in T base, in D data, in M max);
```

**作用：** 对 `data`（可以是字段列表）按 `algo` 算法做哈希，结果 `= (hash(data) ^ base) % max`。常用于 ECMP、负载均衡、会话一致性。

**注意事项：**

- 泛型参数有 4 个：`<O 输出类型, T base 类型, D data 类型, M max 类型>`，p4c 常需**全部显式写出**。
- `data` 必须是 list 表达式（如 `{ srcAddr, dstAddr }`）。
- `base` 通常给 `0`；`max` 决定结果范围（取模）。
- 常用算法：`HashAlgorithm.crc32`、`crc16`、`crc32_custom`、`identity`、`random`。



这里有 **4 个类型参数** `<O, T, D, M>`：

| 类型参数 | 对应实参 | 含义                         |
| :------- | :------- | :--------------------------- |
| `O`      | `h`      | 输出（Output）结果的类型     |
| `T`      | `32w0`   | base 值的类型                |
| `D`      | `{...}`  | data（参与哈希的数据）的类型 |
| `M`      | `32w4`   | max 值的类型                 |

你贴出的四个类型正好一一对应：

**示例（基于五元组做 ECMP，选 0~3 号出口之一）：**

```cpp
apply {
    bit<32> h; // 声明一个 32 位变量 h，用来接收哈希计算结果。
    hash<
    bit<32>, 
    bit<32>, 
    tuple<bit<32>, bit<32>, bit<16>, bit<16>, bit<8>>, 
    bit<32>
    >(
    h,	// 输出：接收哈希结果
    HashAlgorithm.crc32,	// 使用的哈希算法
    32w0,	// 结果最小值，从 0 开始
    { hdr.ipv4.srcAddr, hdr.ipv4.dstAddr, hdr.tcp.srcPort, hdr.tcp.dstPort, hdr.ipv4.protocol },	// 参与哈希的数据
    32w4 // 结果最大值，从 4 开始
    );
    standard_metadata.egress_spec = (bit<9>)h + 1;   // 转发到端口 h+1
}
```

## 13. digest()

**签名（v1model.p4）：**

```cpp
extern void digest<T>(in bit<32> receiver, in T data);
```

**作用：** 把 `data` 上报给控制平面（CPU/软件）的 digest 通道 `receiver`。常用于学习 MAC 地址、上报流量统计、NFV 采样。

**注意事项：**
- 只能配合控制面（如 BMv2 的 `bm_CLI`/Thrift）使用，需要在运行时启用对应的 digest 监听。
- `data` 是字段列表，字段类型必须能被序列化。
- 只上报数据，不会改变包本身。

**示例（把源 MAC + 入端口上报给控制面做 MAC 学习）：**

```cpp
apply {
    digest(1, { hdr.ethernet.srcAddr, standard_metadata.ingress_port });
}
```

## 14. truncate()

**签名（v1model.p4）：**

```cpp
extern void truncate(in bit<32> length);
```

**作用：** 把**输出报文**截断为 `length` **字节**。常用于只转发报文头部（sFlow 采样、首包直通）、减少带宽。

**示例（只转发前 64 字节，其余截断）：**

```cpp
apply {
```

## 15. mark_to_drop()

**签名（v1model.p4）：**

```cpp
extern void mark_to_drop();                                        // 无参版本
extern void mark_to_drop(inout standard_metadata_t standard_metadata);  // 常用版本
```

**作用：** 把报文标记为丢弃（把 `egress_spec` 设为丢弃端口）。**注意：它不会立即终止当前处理**，后续代码仍会执行，但包最终不会发出。

**注意事项：**
- 推荐使用带 `standard_metadata` 参数的版本（BMv2 友好）。
- 与直接赋值 `egress_spec = 0xFFFF` 效果类似，但语义更清晰、可移植。
- 想立即停止处理要用 `exit` 语句。

**示例（访问控制：拒绝来自端口 2 的流量）：**

```cpp
apply {
    if (standard_metadata.ingress_port == 9w2) {
        mark_to_drop(standard_metadata);     // 标记丢弃
    } else {
        standard_metadata.egress_spec = 1;   // 正常转发
    }
}
```

## 16. header stack 方法（next / last / size / push_front / pop_front）

**签名（header stack 内置属性/方法）：**

```cpp
hs.next;                        // 下一个待解析元素的下标（初始 0）
hs.last;                        // 最近解析的元素下标（未解析过则为未定义）
hs.size;                        // 栈中元素个数（编译期常量）
void push_front<T>(in T data);  // 规范形式：压入一个 header（p4c 实现有差异，见下）
void pop_front<T>(out T data);  // 规范形式：弹出一个 header
```

**作用：** header stack 是"相同 header 的数组"，配合这些属性/方法实现**多层协议栈**（MPLS 标签栈、多级隧道）的解析与操作。

**注意事项：**
- `hs.next` 在每次 `extract(hs.next)` 成功后自动 +1；`hs.last` 指向刚解析完的元素。
- `hs.size` 是编译期常量（数组长度），不是"已解析数量"。
- 越界访问触发 `error.StackOutOfBounds`。
- ⚠️ **p4c/BMv2 实现差异**：`push_front(n)` / `pop_front(n)` 的参数是**编译期常量 `count`**（压入/弹出 n 个元素），而不是规范里的 header 数据参数。写跨 Target 代码前先确认。

**示例 1（循环解析多层 MPLS 标签，用 next/last）：**

```cpp
header mpls_h { bit<20> label; bit<3> tc; bit bos; bit<8> ttl; }
struct headers { ethernet_h ethernet; mpls_h[3] mpls; }

state parse_mpls {
    b.extract(hdr.mpls.next);              // 解析到下一个元素，next 自动 +1
    transition select(hdr.mpls.last.bos) { // 看刚解析的那个的 bos 位
        0 : parse_mpls;                    // 栈底标志 0 → 继续压栈
        1 : parse_ipv4;                    // 1 → 到底了，去解析 IP
    }
}
```

**示例 2（在 control 里用 push_front/pop_front 操作标签栈，p4c 写法）：**

```cpp
apply {
    // 在栈顶压入 1 层新标签（新元素为 invalid，需自行赋值）
    hdr.mpls.push_front(1);
    hdr.mpls[0].setValid();
    hdr.mpls[0].label = 20w100;

    // 弹出 1 层标签
    hdr.mpls.pop_front(1);

    bit<32> n = hdr.mpls.size;             // 恒等于 3（数组长度）
}
```

## 17. clone() 系列

**签名（v1model.p4）：**

```cpp
extern void clone(in CloneType type, in bit<32> session);
extern void clone_preserving_field_list(in CloneType type, in bit<32> session, bit<8> index);
extern void clone3<T>(in CloneType type, in bit<32> session, in T data);   // ⚠️ BMv2 未实现
```

**作用：** 复制一份报文投递到指定端口（如镜像到监控口、给控制面副本）。`type` 用 `CloneType.I2E`（ingress 复制到 egress）或 `CloneType.E2E`（egress 复制到 egress）。`session` 是复制会话号，由控制面映射到实际端口。

**注意事项：**
- 复制的副本会**重新进入 egress 流水线**，可用 `clone3`/`clone_preserving_field_list` 携带用户元数据。
- ⚠️ BMv2 支持 `clone` 与 `clone_preserving_field_list`；`clone3` 不支持。
- 配合 `@field_list(index)` 注解的字段才能被 `_preserving_field_list` 保留。

**示例（把进入端口 1 的包镜像到端口 10）：**

```cpp
struct metadata { @field_list(0) bit<16> mark; }

apply {
    if (standard_metadata.ingress_port == 9w1) {
        clone(CloneType.I2E, 32w1);        // 会话 1（控制面把会话 1 映射到端口 10）
        meta.mark = 16w0xCAFE;             // 会被 clone_preserving_field_list 保留
    }
    standard_metadata.egress_spec = 1;     // 原包继续正常转发
}
```

## 18. recirculate() 系列

**签名（v1model.p4）：**

```cpp
extern void recirculate<T>(in T data);                        // ⚠️ BMv2 未实现
extern void recirculate_preserving_field_list(bit<8> index);
```

**作用：** 把报文**重新送进流水线最前端（parser）**再处理一遍，可配合字段列表保留用户元数据。用于多遍处理（如隧道解封装、多轮 ACL）。

**注意事项：**
- ⚠️ BMv2 只支持 `recirculate_preserving_field_list`，且**只能在 egress 中调用**。
- 反复 recirculate 需要控制循环次数，否则会死循环。
- 可用 `standard_metadata.recirculate_port` 指定重入端口。

**示例（egress 中把特殊报文送回重处理一次，BMv2 写法）：**

```cpp
control MyEgress(inout headers hdr, inout metadata meta,
                 inout standard_metadata_t standard_metadata) {
    apply {
        if (hdr.ethernet.etherType == 0x8847) {   // MPLS 报文再重处理一次
            recirculate_preserving_field_list(8w0);
        }
    }
}
```

## 19. resubmit() 系列

**签名（v1model.p4）：**

```cpp
extern void resubmit<T>(in T data);                           // ⚠️ BMv2 未实现
extern void resubmit_preserving_field_list(bit<8> index);
```

**作用：** 把报文重新提交给 parser，**保留解析前的原始报文内容**（与 recirculate 的区别：resubmit 从原始报文开始，不保留已做的修改）。常用于"先粗查一次，再精查一次"。

**注意事项：**
- ⚠️ BMv2 只支持 `resubmit_preserving_field_list`，且**只能在 ingress 中调用**。
- 注意与 recirculate 的位置要求相反：resubmit 在 ingress，recirculate 在 egress。

**示例（ingress 里对带内 OAM 报文 resubmit 重新解析，BMv2 写法）：**

```cpp
struct metadata { @field_list(0) bit<32> first_pass; }

control MyIngress(inout headers hdr, inout metadata meta,
                  inout standard_metadata_t standard_metadata) {
    apply {
        if (hdr.ethernet.etherType == 0x88b5) {   // 首次处理特殊报文
            resubmit_preserving_field_list(8w0);  // 重新提交给 parser
        }
        standard_metadata.egress_spec = 1;
    }
}
```

## 20. assert() / assume()

**签名（v1model.p4）：**

```cpp
extern void assert(in bool check);   // 条件为 false 时抛错，终止处理
extern void assume(in bool check);   // 提示编译器"这里恒成立"，可被优化利用
```

**作用：** 调试辅助。`assert` 失败会报错（BMv2 下会在日志中打印并中断该包处理）；`assume` 声明一个不变量，帮助编译器优化、做形式化验证。

**注意事项：**

- 不建议在正式数据平面代码里大量使用 `assert`（有副作用，影响性能）。
- BMv2 中 `assert` 失败表现为运行时错误记录。

**示例（调试时检查元数据不变量）：**

```cpp
struct metadata { bit<32> count; }

apply {
    meta.count = meta.count + 1;
    assert(meta.count > 0);              // 正常不会失败
    assume(meta.count < 1000000);        // 告诉编译器计数不会超大
}
```

## 21. log_msg()

**签名（v1model.p4）：**

```cpp
extern void log_msg(string msg);
extern void log_msg<T>(string msg, in T data);   // data 必须是 list 表达式
```

**作用：** 向调试日志输出一条消息（可带字段数据）。用于排障。

**注意事项：**

**示例：**

```cpp
struct metadata { bit<16> port; }

}
```

## 22. 有状态 extern（register / counter / meter / direct_* / action_profile）

这些是**有状态的 extern 对象**，需要先实例化再调用其方法。

### 22.1 register（寄存器）

**签名（v1model.p4）：**

```cpp
extern register<T, I> { register(bit<32> size); void read(out T result, in I index); void write(in I index, in T value); }
extern register<T>    { register(bit<32> size); void read(out T result, in bit<32> index); void write(in bit<32> index, in T value); }
```

**作用：** 跨包的存储数组（数据平面自己的内存），常做计数器、流状态、隧道统计。

**注意事项：**

- 读写在**同一 action 内并发语义**由 Target 决定（BMv2 单线程安全）。
- `I` 是索引类型，通常 `bit<32>`。

**示例（按端口计数）：**

```cpp
register<bit<32>>(16) port_counter;      // 16 个 32 位计数器

apply {
    bit<32> idx = (bit<32>)standard_metadata.ingress_port;
    bit<32> val;
    port_counter.read(val, idx);         // 读旧值
    port_counter.write(idx, val + 1);    // 写回 +1
}
```

### 22.2 counter / direct_counter（计数器）

**签名（v1model.p4）：**

```cpp
extern counter { counter(bit<32> size, CounterType type); void count(in bit<32> index); }
extern direct_counter { direct_counter(CounterType type); void count(); }
```

**作用：** 高性能计数（包数/字节数）。`CounterType.PACKETS` / `CounterType.BYTES` / `CounterType.PACKETS_AND_BYTES`。`direct_counter` 直接挂在某张表上，表命中自动计数。

**注意事项：**
- 需要控制面查询/清零。
- `direct_counter` 只能在对应表上计数。

**示例（普通 counter）：**

```cpp
counter(1024, CounterType.BYTES) ctr;

apply {
    ctr.count((bit<32>)standard_metadata.ingress_port);
}
```

**示例（direct_counter 随表计数）：**

```cpp
direct_counter(CounterType.PACKETS) dc;

table t {
    key = { hdr.ethernet.dstAddr : exact; }
    actions = { forward; NoAction; }
    counters = dc;              // 表命中即计数
    default_action = NoAction();
}
```

### 22.3 meter / direct_meter（限速器）

**签名（v1model.p4）：**

```cpp
extern meter { meter(bit<32> size, MeterType type); void execute_meter(in bit<32> index, out MeterColor color); }
extern direct_meter<T> { direct_meter(MeterType type); void read(out T color); }
```

**作用：** 三色令牌桶限速。`MeterType.BYTES` / `PACKETS`。输出颜色 `MeterColor.GREEN/YELLOW/RED`，程序据此决定转发/标记/丢弃。

**注意事项：**
- 结果颜色可用于标记 DSCP 或做丢弃决策。

**示例（按端口限速，超速 RED 丢弃）：**

```cpp
meter(16, MeterType.BYTES) m;
MeterColor color;

apply {
    m.execute_meter((bit<32>)standard_metadata.ingress_port, color);
    if (color == MeterColor.RED) {
        mark_to_drop(standard_metadata);
    }
}
```

### 22.4 action_profile / action_selector（动作间接表）

**签名（v1model.p4）：**

```cpp
extern action_profile { action_profile(bit<32> size); }
extern action_selector { action_selector(HashAlgorithm algorithm, bit<32> size, bit<32> outputWidth); }
```

**作用：** 把动作从表项中抽离共享（action profile），或按哈希选择组成员（action selector，用于 ECMP/组播组）。通常通过表的 `implementation` 属性挂接。

**示例（action profile 挂到表上）：**

```cpp
action_profile(1024) ap;

table t {
    key = { hdr.ipv4.dstAddr : lpm; }
    actions = { forward; drop; NoAction; }
    implementation = ap;          // 共享动作集，控制面可复用
    default_action = NoAction();
}
```

## 23. 编译期大小函数（sizeof / maxSizeInBits / minSizeInBits）

**语法（规范 §9）：**

```cpp
sizeof<T>();          // 返回 T 的位宽（编译期常量）
maxSizeInBits<T>();   // T 的最大可能位宽（含 varbit 上限）
minSizeInBits<T>();   // T 的最小可能位宽
```

**作用：** 在编译期确定一个类型的尺寸，可用于表容量计算、varbit 边界校验等。

**注意事项：**
- 是**编译期函数**，结果必须是编译期常量表达式。
- ⚠️ p4c 当前**未实现**这三个函数（报 `declaration not found`），使用前先确认你的编译器/Target。
- 对于不含 varbit 的类型，三个函数返回相同结果。

**示例（规范示范，p4c 暂不支持）：**

```p4
header ipv4_h { bit<4> version; bit<4> ihl; bit<16> totalLen; bit<32> srcAddr; bit<32> dstAddr;
                varbit<320> options; }
// sizeof<ipv4_h>()        → 固定部分 88 位
// maxSizeInBits<ipv4_h>() → 88 + 320 = 408 位
// minSizeInBits<ipv4_h>() → 88 位
```

## 24. 已废弃：Checksum16

**签名（v1model.p4，已标注 @deprecated）：**

```cpp
extern Checksum16 {
    Checksum16();               // 构造函数
    bit<16> get<D>(in D data);  // 一次性计算 data 的校验和
}
```

**作用：** 旧式校验和计算组件。**注意**：v1model 中的 `Checksum16` **只有 `get(data)` 一个方法**，没有规范附录 E 里写的 `clear/update/remove`。p4c 会给出 deprecated 警告，建议改用第 10 节的 `verify_checksum`/`update_checksum`。

**注意事项：**
- extern 对象必须**构造式实例化**：`Checksum16() ck;`（不能 `Checksum16 ck = Checksum16();`）。
- BMv2 后端不支持在 parser 里用 `get()` 做校验，请在对应的 Verify/Compute control 用 `verify_checksum`/`update_checksum`。

**示例（了解即可，推荐别用）：**

```cpp
// ⚠️ 以下写法在 BMv2 后端不可用（仅作概念演示）
control MyComputeChecksum(inout headers hdr, inout metadata meta) {
    Checksum16() ck;
    apply {
        hdr.ipv4.hdrChecksum = ck.get(hdr.ipv4);   // 概念示意，实际请用 update_checksum
    }
}
```
