# 模型论文合集

## 1 量化节点

>**title:** A_Machine_Learning-Based_Toolbox_for_P4_Programmable_Data-Planes
>
>**venue:** IEEE TNSM
>
>**year:** 2024 年 8 月
>
>**link:**  [A_Machine_Learning-Based_Toolbox_for_P4_Programmable_Data-Planes.pdf](..\论文存放\model\A_Machine_Learning-Based_Toolbox_for_P4_Programmable_Data-Planes.pdf) 

### 1.1 一句话总结
> 由于神经网络在迭代过程中会产生大量浮点数，而 P4 数据平面不支持存储浮点数。该论文通过引入**量化节点（Quantization Node）**，解决在 P4 可编程数据平面部署神经网络模型时精度缺失的问题，并从理论上证明了该模型**精度损失的上界**。
>
> **补充一句更完整的理解**：论文不只是提出量化方法，而是构建了一个**端到端的工具箱（Toolbox）**，让 ML 模型（尤其是神经网络）能够**自动量化、映射、部署**到 P4 数据平面，同时给出**误差可控的理论保证**。

### 1.2 研究背景与问题

| 项目             | 内容                                                         |
| :--------------- | :----------------------------------------------------------- |
| **背景**         | P4 可编程交换机支持线速处理，但数据平面**不支持浮点运算**，只支持整数、位运算、有限寄存器 |
| **问题**         | 直接在 P4 上部署神经网络 → 浮点转定点 → **精度损失**，且损失多少**没有理论保证** |
| **现有工作不足** | 大多只做工程量化，缺少**误差上界证明**；或只支持简单模型（决策树），不支持神经网络 |
| **本文目标**     | 提供一套**自动量化 + 部署 + 误差保证**的工具箱               |

### 1.3 系统设计

**量化公式**
$$
\hat{r} = \text{clamp}\left(\left\lfloor \frac{r}{S} \right\rfloor + Z; Q_{\min}, Q_{\max}\right)
$$

**反量化公式**
$$
\tilde{r} = S(\hat{r} - Z)
$$

**四个量化参数**

| 参数            | 含义                                 | 解释                                       |
| --------------- | ------------------------------------ | ------------------------------------------ |
| $\alpha, \beta$ | 裁剪范围                             | 训练过程中，对各层权重做统计，最小和最大数 |
| $S$             | 缩放因子，一个整数格子代表多少浮点值 | 类似于0.01或0.0127，这种最小保留精度       |
| $Z$             | 零点偏移                             | 如果大部分都是负数需要位移到Qmin与Qmax中   |
| $B$             | 位宽                                 | 需要多少精度等于(max-min)/位宽             |

$$
S = \frac{\beta - \alpha}{2^B - 1}
$$

---

**量化感知训练（QAT）**

权重：

$$
W \rightarrow \hat{W} \rightarrow \tilde{W}
$$

激活：

$$
r \rightarrow \hat{r} \rightarrow \tilde{r}
$$

---

**校准**

确定最终 $[\alpha, \beta]$。

---

**P4 部署**
$$
\hat{r}_k^i = Z^i + M^i \left(\sum_{l} \left(\hat{r}_l^{i-1} - Z^{i-1}\right)\left(\hat{w}_{kl}^i - Z_w^i\right) + \hat{\rho}_k^i\right)
$$

$$
M^i = \frac{S^{i-1} S_w^i}{S^i}
$$

### 1.4 优缺点

**优点**：

- 端到端工具箱，训练到部署全流程；
- 不需要修改交换机硬件；
- 有严格的理论误差上界；
- 支持 MLP、1D-CNN 等神经网络；
- QAT 有效补偿量化误差。

**缺点**：

- 只支持单交换机部署，大型模型需分布式方案；
- 计算复杂度随矩阵规模增长，可能影响线速；
- 激活范围依赖校准数据，校准不充分会影响精度；
- 不支持原始字节特征，信息量受限；
- 需要目标支持乘法，否则要分解成移位和加法。

### 1.5 与其他论文的关系

| 论文                | 关系                                      |
| :------------------ | :---------------------------------------- |
| MAP4、pHeavy        | 只支持决策树，硬编码 if-else              |
| pForest、SwitchTree | 层表映射决策树，深度受限                  |
| Itsy、Planter       | 特征决策映射，支持随机森林                |
| Mousika             | 二值决策树 + 知识蒸馏                     |
| NNSplit、SOREN      | BNN 拆分到多交换机                        |
| IOI、Taurus         | 修改交换机硬件支持 DNN                    |
| **INQ-MLT**         | **不修改硬件，用量化 + QAT 支持神经网络** |

**定位**：在“不修改硬件”这一约束下，首次系统性地支持神经网络在 P4 上部署，并给出理论误差保证。

### 1.6 可借鉴点

1. **量化感知训练 + 整数推理** 的完整流程可复用到其他资源受限平台；
2. **模板化 P4 代码生成** 思路可推广到其他模型；
3. **理论误差上界** 可用来指导位宽和裁剪范围选择；
4. **校准数据** 思路可用于任何量化部署场景；
5. **STE 反向传播** 是 QAT 的关键技巧；
6. **并集上界 + 切比雪夫不等式** 的误差分析框架可迁移到其他量化模型。





## 1 AdaFlow

> **title:** AdaFlow: Efficient In-Network Traffic Classification using Programmable Switches
> **venue:** IFIP Networking Conference
> **year:** 2024
> **link:**  [AdaFlow_Efficient_In-Network_Traffic_Classification_using_Programmable_Switches.pdf](..\论文存放\model\AdaFlow_Efficient_In-Network_Traffic_Classification_using_Programmable_Switches.pdf) 

### 1.1 一句话总结

> 由于可编程交换机数据平面存在**每包操作受限**和**有状态内存有限**的约束。AdaFlow 通过**包分类**和**流分类**并行工作，PrioritySketch 解决**流冲突**（多阶段聚合 ML 模型 +  + Profiler 自动配置）

> **补充一句更完整的理解**：配置时通过 **Profiler** 自动搜索最优超参数和硬件参数。核心目标是**在低内存下实现高准确率**。

------

### 1.2 研究背景与问题

| 项目             | 内容                                                         |
| :--------------- | :----------------------------------------------------------- |
| **背景**         | 可编程交换机支持线速网络内流量分类，但交换机内存有限（几十 MB），且每包操作和状态内存受限 |
| **问题**         | 现有系统在**分类准确率**和**内存开销**之间存在根本权衡：只用 PL 特征准确率差；只用 FL 特征延迟高且易漏检；PL+FL 系统要么内存开销大（NetBeacon），要么推理点单一（Jewel） |
| **现有工作不足** | NetBeacon 使用多个 ML 模型，内存开销高；Jewel 使用单一统一模型，但只有**一个推理点**，对多样化流量准确率差；两者都**没有冲突处理机制** |
| **本文目标**     | 设计一个**通用、内存高效、准确**的网络内分类器，能准确分类具有多样化流特征的流量，同时保持低数据平面内存占用 |

------

### 1.3 系统设计

**一、蓝路径（Blue Path）**

**触发条件**：数据包所属的流**没有发生哈希冲突**，且该流当前包数 **< n**（n 是切换到使用流级特征的阈值包数）。

**情况 1：满足超时或 RST/FIN 标志（实线路径）**

- 提取**包级特征**，检查是否发生 **timeout**（空闲超时或活跃超时）或数据包带有 **RST/FIN** 标志。
- 如果满足：
  - 读取**流级特征**；
  - 将流级特征**重置**为当前包的包级特征；
  - 用 ML 模型推理该流的类别；
  - 如果是**恶意流**，将其 `flow_ID` 作为 **digest 消息**发送给控制器。
- 控制器收到 digest 后，会通过 **FU（Flow Update）** 安装用户定义的规则到**包转发表**中，例如：对后续相同 5 元组的包执行 **drop** 或 **转发到特定端口**进一步分析。

**情况 2：不满足条件（虚线路径）**

- **更新流级特征**；
- 当前包**仅使用包级特征**进行分类；
- 直到包计数达到 **n** 为止。

最后，AdaFlow 会应用**用户定义的、按类别区分的包处理规则**：

- 若判定为恶意 → drop 或送控制器；
- 否则 → 跳过，转发到数据平面的下一个模块。

------

**二、橙路径（Orange Path）**

**触发条件**：无冲突，且流的数据包数量 **≥ n**。

- 如果满足超时或 RST/FIN 条件 → 路径与蓝路径的实线部分相同。
- 否则（虚线橙线）：
  - **更新流级特征**；
  - 用 ML 模型推理流类别；
  - 如果预测置信度 **P(y) > dt**（判定阈值），则将**流优先级存储**中的优先级标志设为 **0**（初始全为 1）。
  - 这个优先级更新会用于 **PrioritySketch 算法**的冲突处理，以实现高准确率（D3）和低内存开销（D2）。
  - 同时，数据平面将 `flow_ID` 和 `class_ID` 共享给控制器，并应用用户定义的类别特定包处理规则。

------

**三、红路径（Red Path）**

**触发条件**：新来的包与**已驻留的流发生冲突**。

执行路径取决于**驻留流的优先级**：

**情况 1：优先级 = 1（实线）**

- 表示驻留流**尚未被分类**（未达到判定阈值），因此它被**优先保留**，因为它的流级特征还不可靠。
- 此时，**新来的包仅使用包级特征进行分类**。

**情况 2：优先级 = 0**

- 表示驻留流的流级特征**已足够确定其类别**，可以被替换。
- 操作：
  - 优先级重置为 **1**；
  - 流级特征用新包的包级特征**重新初始化**；
  - 应用用户定义的类别特定包处理规则。
- 更多细节在 **§IV（PrioritySketch 算法）** 中。

#### 1.3.3 PrioritySketch 算法

**离线优先级分配**：

每条推理规则 r带两个值：推理类别 y(r) 和置信度 P(y∣r)∈[0,1]。

对恶意流和正常流分别使用阈值 dtM和 dtB：
$$
priority(r) = 1 - \mathbb{1}\{P(y = mal \mid r) > dt_M\}, \quad y(r) = mal
$$

$$
priority(r) = 1 - \mathbb{1}\{P(y = ben \mid r) > dt_B\}, \quad y(r) = ben
$$

多分类推广：
$$
priority(r) = 1 - \mathbb{1}\{P(y = c \mid r) > dt_c\}, \quad y(r) = c
$$
其中 c∈[k]*c*∈[*k*] 是 k*k* 类多分类问题中与规则 r*r* 关联的类别标签。

**运行时优先级更新**：

当流超过判定阈值并映射到规则r时：
$$
priority(r) \leftarrow 0 \quad \text{若} \quad P(y) > dt
$$
否则保持 priority(r)=1。

**冲突处理逻辑**：

- 若驻留流 priority=1 → 优先保留，新包仅用 PL 特征分类；
- 若驻留流 priority=0 → 允许替换，优先级重置为 1，FL 特征重新初始化。

#### 1.3.4 Profiler 自动配置

**四步工作流程**：

1. 对每组配置 hp, hw(超参数, 硬件参数)，按训练模型 MLa：

$$
ML_a = \text{Train}(hp, hw, [FL, PL])
$$

2. 用递归特征消除（RFE）选最佳特征数：

$$
ML_b = \text{BEST}(\text{RFE}(ML_a), n\_feats)
$$

3. 用截断策略把时间类特征塞进硬件内存：

$$
ML_{final} = \text{BEST}(ML_b, \text{TRUNCATE}(time\_feats))
$$



1. 在整个 hp,hw 搜索空间重复 1–3，得到最终模型。

**选择标准**（最大化 reward）：
$$
reward = \alpha \cdot F1 + (1 - \alpha) \cdot (1 - \rho)
$$
其中F1：分类的 F1 分数;  ρ是目标交换机总内存占用比例，α∈[0,1]，实验中取 α=0.5。

**超参数 hp**：

| 参数             | 含义                                |
| :--------------- | :---------------------------------- |
| 触发包 n         | 切换到 PL+FL 推理的包数阈值         |
| 树数量           | 随机森林/XGBoost 的树数             |
| 树深度           | 决策树最大深度                      |
| 判定阈值 dt      | 确认分类的置信度阈值（含 dtM、dtB） |
| 空闲超时 δidle   | 流空闲多久被驱逐                    |
| 活跃超时 δactive | 流活跃多久被驱逐                    |
| bin 宽度         | 特征离散化的区间宽度                |

**硬件参数 hw**：

| 参数                   | 含义               |
| :--------------------- | :----------------- |
| 叶子数                 | 决策树叶子节点数   |
| 寄存器条目数           | 流状态存储的条目数 |
| 寄存器条目大小（bits） | 每个条目的位宽     |

### 1.4 优缺点

**优点**：

- **模型训练**：将PL+FL特征同时丢进去模型里训练，FL有的特征但PL没有的特征用一个不可到达数进行赋值；
- **密集推理点**：通过数据增强在多个阶段准确推理，优于 NetBeacon 的稀疏推理点和 Jewel 的单推理点；
- **PrioritySketch 冲突解决**：基于流量特定优先级，在内存冲突时优先保留重要流，提升召回率；
- **Profiler 自动配置**：自动搜索最优超参数和硬件参数，减少人工调参；
- **通用性**：支持多种流量分析任务（Covert channel、P2P botnet、DDoS、入侵检测等）；
- **n的取值：** Is={*n*,*n*+Δ,*n*+2Δ,…,*n*+*k*Δ}∪2^i，n=2^i使得这个流的均值除法操作可以用移位来替代

**缺点**：

- **依赖流量特定启发式**：不同数据集需要 Profiler 重新搜索配置；
- **阈值需自动优化**：dtM、dtB依赖数据集特性，不是通用值；
- **哈希冲突仍存在**：即使有 PrioritySketch，高冲突率下仍可能影响精度；
- **FL 特征计算限制**：某些 FL 特征（如平均/方差）涉及除法，只能在少数2i推理点用位移计算；
- **只支持决策树类模型**：论文主要用决策树（DT）、随机森林、XGBoost，不支持神经网络；
- **单交换机部署**：大型模型或高并发流场景可能需要分布式方案；
- **控制器交互开销**：digest 消息速率与流完成率、超时率、阈值到达率成正比，可能增加控制平面负担。

------

### 1.5 与其他论文的关系

| 论文                     | 关系                                                         |
| :----------------------- | :----------------------------------------------------------- |
| **Mousika**              | 只用 PL 特征，二值决策树 + 知识蒸馏；AdaFlow 用 PL+FL        |
| **Planter**              | 只用 PL 特征，层表映射决策树；AdaFlow 用 PL+FL 且支持密集推理 |
| **Flowrest**             | 只用 FL 特征，单推理点；AdaFlow 用 PL+FL，密集推理点         |
| **NetBeacon**            | PL+FL，稀疏推理点（4–10 个），多个 ML 模型，内存开销大；AdaFlow 用单一聚合模型 |
| **Jewel**                | PL+FL，单推理点，单一统一模型，内存高效但准确率差；AdaFlow 用密集推理点 |
| **Mousika / Planter**    | 只支持决策树，硬编码 if-else；AdaFlow 支持 DT/RF/XGBoost     |
| **pForest / SwitchTree** | 层表映射决策树，深度受限；AdaFlow 无此限制                   |
| **NNSplit / SOREN**      | BNN 拆分到多交换机；AdaFlow 单交换机                         |
| **IOI / Taurus**         | 修改交换机硬件支持 DNN；AdaFlow 不修改硬件                   |
| **INQ-MLT**              | 不修改硬件，量化 + QAT 支持神经网络；AdaFlow 用决策树 + 量化替代方案 |

**定位**：在“不修改硬件”约束下，首次系统性地**同时支持 PL+FL 特征、密集推理点、冲突处理、自动配置**，并在多个数据集上验证了低内存高准确率。

------

### 1.6 可借鉴点

1. **单一聚合模型 + 数据增强**：用数据增强让一个模型覆盖多个阶段，可复用到其他资源受限平台；
2. **不对称阈值策略**：恶意流高阈值、正常流低阈值，用代价不对称换取召回率，可迁移到其他安全分类场景；
3. **PrioritySketch 冲突解决**：基于优先级的流状态保留/驱逐机制，可复用到任何哈希表冲突场景；
4. **Profiler 自动配置**：用 reward = α·F1 + (1−α)·(1−ρ) 平衡准确率和内存，可迁移到其他 ML 部署场景；
5. **样本权重设计**：w(S)=nePktCount/n−1 随包数指数增长，让长流主导训练，可复用到类别不平衡场景；
6. **密集推理点设计**：在 {n,n+Δ,… }∪2i{*n*,*n*+Δ,…}∪2*i* 处生成样本，兼顾覆盖率和内存；
7. **φ 不可达值**：早期样本 FL 填 φ 而非 0，避免与真实 FL=0 混淆，是特征缺失处理的经典技巧；
8. **理论 + 实验结合**：论文不仅有实验，还有 FL 特征计算限制、冲突率分析等理论支撑。
