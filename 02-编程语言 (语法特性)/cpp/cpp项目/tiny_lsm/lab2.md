### 2.2.1 合并迭代器的必要性

假如skipList0是活跃表，skipList1是冻结表

```cpp
SkipList0: ("k1", "v1") -> ("k4", "") -> ("k5", "v3")
SkipList1: ("k2", "v2") -> ("k3", "v3") -> ("k4", "v4")
```



对于**单个key的查询**：

- 只需要从最新的SkipList0开始查
- 如果找到就返回（即使是删除标记）
- 没找到才去查SkipList1
- 这样确实不需要合并多个SkipList

这样保证了单个key的查询一定是最新的，如果被删除了，那么一定会查出("k4", "")，而不是("k4", "v4")



但是对于**范围扫描**（比如`Scan("k1", "k5")`）：

- 需要在多个SkipList上同时遍历
- 因为每个SkipList可能包含不同范围的key
- 需要合并成一个有序的结果集



比如你要扫描所有key：

```cpp
SkipList0: k1 → k4(删除) → k5
SkipList1: k2 → k3 → k4(有效)
```

如果只遍历SkipList0：

- 你会看到：k1, k4(删除), k5
- 错过了SkipList1中的k2和k3

如果只遍历SkipList1：

- 你会看到：k2, k3, k4(有效)
- 但k4应该是被删除的，你得到了旧值

所以需要用堆来合并多个SkipList的迭代器
